# Hardware substitution and legacy experiment
The owner's image is a historical table experiment, not the final BOM. It depicts ESP8266 NodeMCU, ZMCT103C5A, USB phone charger and ordinary5V Songle relay. The label and drawn wires conflict (A0 vs D3 sensor output, D1 vs D2 relay input, and3V labeled as5V). Do not implement or copy those connections as verified wiring. A photograph/diagram cannot determine analog input voltage compatibility or mains isolation.

Reference final board: classic dual-core ESP32-WROOM-32 DevKit; pins in include/hardware_config.hpp. SCT-013 current-output vs voltage-output SKUs need different burden/bias circuitry. ZMPT101B modules need conditioned ADC-safe output and calibration. A 5V module output must not directly exceed3.3V ESP32 ADC input. Latching relay requires pulse driver and auxiliary feedback, not the ordinary relay module's held logic input. Transformer may require three-phase metering; the current reference profile is explicitly single-phase until topology/BOM is confirmed.

## Changes centralized here
Pin names/UART speed/coil timings live in hardware_config.hpp. Calibration coefficients and version must come from bench measurements. Device role chosen by PlatformIO environment; relay fitted is separate commissioned capability, not guessed from plan. Board variant selected in platformio.ini. Modem APN/credentials, device ID/keys, peer addresses, RS485 address, trusted CA, site topology and server origin are runtime provisioning, not compiled public constants. Test keys in vectors.json are intentionally public and forbidden in deployments.

## What is not a one-line substitution
ESP8266→ESP32, SIM800→SIM7000, UART meter→DLMS meter, CT current-output→voltage-output, single→three-phase and non-latching→latching relay change interfaces/timing/electrical design. Implement/test the specific adapter. Abstract policy/runtime/crypto stays shared. All unknown calibration returns uncalibrated; absent modem/radio returns transport_unavailable; missing IR protocol returns unsupported_meter. Do not plug holes with fake data or insecure transport.

## Adapter contract
Journal.append sets durable per-boot sequence; full storage reports false, leaves data gap explicit and blocks enabling ON until reviewed. persistCommand atomically records replay counter and immutable pending receipt before driver request. Actuator.feedback must use actual qualified auxiliary circuit; request is bounded asynchronous absolute-state actuation with interlocked coils, watchdog and cooldown. ADC adapter samples enough full cycles, phase-corrects and marks clipping/gaps. Transport implements protocol v1, preserves originals across forwarding, retries only immutable message identity. No adapter may run a blocking network call in the safety task.

The Arduino entrypoint remains bench-only. It does not instantiate these hardware adapters; this fact is intentionally visible. New runtime/crypto libraries are portable verified reference logic. Implementing and qualifying sensor, flash, modem, local-link, BLE and OTA adapters remains real engineering work; no document can truthfully label them complete for unspecified hardware.
