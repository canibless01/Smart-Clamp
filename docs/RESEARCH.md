# Public product and official integration review

Reviewed 12 November 2026. HTTPS access is available in this environment. The following are public observations and published contracts, not access to another company's private backend. No real customer meter, merchant transaction or physical ESP32 was used. The shared-desktop tool was unavailable; Chromium rendering initially encountered a proxy CA trust error. Public site/document bodies were retrieved with normal certificate-verified HTTPS; no TLS bypass was used.

| Source | Observed contract/pattern | Implemented consequence / boundary |
|---|---|---|
| [Vendr homepage](https://vendr.ng/) | Current homepage advertises estate management, utility vending and electric/water/gas devices, plus a meter-number/amount form for reviewing incomplete transactions. Its footer says it is sub-metering behind an approved utility meter and not electricity resale/distribution. | Preserve separate utility meter versus room sub-account concepts and uncertain-payment recovery. Do not claim its private implementation, live balance API, reliability, prices or partnership applies to SmartClamp. The earlier source statement that it had abandoned hardware does not match this current public page. No private lookup or purchase was attempted. |
| [Paystack webhooks](https://paystack.com/docs/payments/webhooks/) | Current docs describe timestamped `Paystack-Signature`, rotating `whsec_` secrets, HMAC-SHA512 over `t.raw_body`, a 300-second window, plus legacy `x-paystack-signature` transition support. Provider retries/resends are not business idempotency. | Added current signing/rotation/replay checks without downgrade after modern mode is configured. Retain independent transaction verification and exactly-once credit. Merchant activation and live retry/rotation tests remain external gates. |
| [VTPass electricity API](https://vtpass.com/documentation/ikedc-ikeja-electricity-distribution-company-payment-api/) | Account validation, explicit service IDs, prepaid token delivery, same-request-ID requery. Published successful responses include `requestId`, amount, exact token text and actual `units`, e.g. a string ending in `kWh`. | Pin destination at quote; verify vend identity/amount; keep quoted units as estimates and credit actual delivered units. Unknown/missing units stay reserved and requery the same vend, never charge again. Other DisCo contracts still need their own live catalogue/account tests. Root `debtAmount`, tax and other provider fields may affect actual units; do not promise that tariff estimation equals delivery. |
| [Africa's Talking sending docs](https://developers.africastalking.com/docs/sms/sending), [official SMS SDK](https://github.com/AfricasTalkingLtd/africastalking-python/blob/master/africastalking/SMS.py), [official service transport](https://github.com/AfricasTalkingLtd/africastalking-python/blob/master/africastalking/Service.py) | Form-encoded `/version1/messaging`, username/to/message/from/bulkSMSMode and `apiKey` header; per-recipient provider result/message ID. No caller-supplied standard-SMS idempotency key is documented by this SDK. | Added opt-in durable SMS dispatch with intent committed before HTTP. Uncertain outcomes never blindly resend; accepted is not delivered. Real sender approval, route/cost/handset acceptance and authenticated delivery reporting remain external work. |
| [Espressif OTA](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/ota.html) | Inactive application partitions, pending verification, valid-app marking/rollback, image/security compatibility; bootloader and partition configuration matter. | Added signed artifacts, explicit cohorts, authenticated streaming, exact image hashing, durable reboot intent and signed boot results. Actual power-cut, rollback, secure-boot/flash-encryption and production health qualification remain physical gates. |
| [Espressif ESP-NOW](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/network/esp_now.html) | Provisioned encrypted peers, channel constraints, bounded frames, and radio send status distinct from an application/cloud commit. | Added bounded fragmentation/CRC/reassembly with reorder/duplicate/conflict/timeout/capacity tests. This does not instantiate a radio HAL or prove range. End-device HMAC and exact cloud ACK remain separate. |
| [OpenEnergyMonitor AC power theory](https://docs.openenergymonitor.org/electricity-monitoring/ac-power-theory/introduction.html) | Real power is waveform-average instantaneous v×i; RMS multiplication is apparent power. Phase and acquisition error affect accuracy. | Preserve true-power core and refuse unknown calibration. Source-proposed generic analog wiring cannot establish safe ADC range, phase correction or metering accuracy. |

Octopus documentation and ESPHome reference URLs were also probed, but the attempted endpoints did not all return usable documents; no implementation claim is based on those failed requests. Emporia/Sense remain product references from the earlier owner-supplied material, not an assumed supported private API. Official source contracts take precedence over copied source snippets and competitor marketing.
