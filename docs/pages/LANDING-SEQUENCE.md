# Landing page build sequence and copy brief
Proposed desktop and mobile design; no website implementation is authorized yet. Read source master 14.1 and page 1 alongside this brief.

1. Header: left SmartClamp wordmark; desktop center How It Works / For Landlords / For Homeowners / Pricing; right Validate Your Meter / Log In / Sign Up. Mobile collapses navigation behind a labeled menu; meter CTA remains visible. Transparent over hero becomes white with navy text after hero edge. Menu closes on Escape and returns focus.
2. Hero: desktop 7/5 text/illustration split; phone headline, meter form, illustration. Headline “Electricity you can verify — with or without a meter.” Supporting copy “See what you use. Understand what you pay. Control power where your device supports it.” Source problem slider is a secondary frosted panel, never swaps the form or keyboard focus. Proposed slide topics: fair room allocation, evidence for estimated bills, usage visibility, optional power control. Manual controls and pause; reduced motion uses a static first panel.
3. MeterLookup: label “Enter your meter number”; preserve leading zeros. Provider selector only if real adapter requires it. Primary “Check meter” submits by button or Enter. Idle / validating / valid / not-found / invalid-input / provider-unavailable / rate-limited states are distinct. Valid result shows permitted masked identity and “Validation confirms this account. Live balance and history require a supported connection.” Actions “Explore IR-Reader” and optional “Save with an account.” No signup required for validation. Do not silently store anonymous lookups or expose full home addresses.
4. Demo: realistic responsive graph, wattage, balance, status toggle, always labeled “Interactive demo — simulated data.” User toggles simulated state only; click cue visual, sound off. Reduced motion updates discretely. Desktop side caption, mobile below; text values accessible outside SVG.
5. Four steps: “Measure” / “Connect” / “Verify” / “Manage.” Device illustrations, short explanation and install link. Use a qualified install explanation, not a claim that mains voltage/relay installation is safe without isolation. Add existing-meter link back to lookup.
6. Audience cards: Shared Housing → /for-landlords; Single Home → /for-homeowners; Already Smart → lookup anchor. Desktop 3 columns, phone stacked; one accessible link per card, no nested buttons.
7. Trust strip: source proposes 3-minute install and 5-layer detection. Publish only supported claims: “Metered or unmetered options”, “Offline buffering by design”, “Evidence with clear provenance”, “Optional relay control”. Label features in development until tested; no certification logos without approval.
8. Pilot proof: “Piloting in the FUTA area — verified results coming soon.” No invented testimonials, adopter count, savings or live uptime counter. Real pilot outcomes require period/sample size/source and permission.
9. Pricing preview: Free, Basic, Basic Pro, Pro; separate “Shared housing? Talk to us.” Explicitly distinguish recurring platform subscription from electricity credit, hardware and install cost. Free validation ₦0; unapproved paid prices read “Pricing being finalized”, not fabricated naira figures. Full comparison links /pricing.
10. Final glass panel: “Know your usage. Keep your evidence.” Primary “Get started”, secondary “Check your meter”. Phone full width buttons, desktop inline; 48px minimum separation from decorative elements.
11. Footer: Product / Support / Company links to all public inventory pages. Source disclaimer: “SmartClamp provides sub-metering and verification technology. It does not generate, resell, or distribute electricity, and does not replace your utility meter.” Legal wording still needs professional review. Contact fields only confirmed channels.

Acceptance: 320px without page overflow; phone landscape and 200% zoom; 768px tablet; 1440px desktop; form keyboard and screen-reader feedback; slow provider response; real invalid meter; failed network; rate limit; reduced motion; JS disabled still exposes content and usable navigation. No actual live lookup claim until provider sandbox and authorization verified. Do not connect demo toggles to real command endpoints.
