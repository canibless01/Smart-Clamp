# B5. Support Case Detail
Route `/support/tickets/[id]`. Audience: reporter/assigned support. Foundation addition to close an implicit product flow; not an extra approved hardware product.

## Content in reading order
Case reference/category/status/assigned team; event/payment/command context; private conversation/attachments; response expectations.

## Buttons and behavior
Reply; upload evidence; reopen; return dashboard.

POST reply idempotent; attachments scanned/private; optional external helpdesk adapter must preserve case identity and access audit. Dangerous electrical symptoms direct to qualified local help, not remote software repair claim.

## State and layout acceptance
Apply WEB-STATE-MACHINES.md: stable skeleton, honest empty/unsupported, field errors preserving input, unavailable provider, stale source with timestamp, forbidden scope and retriable safe reads. Financial/control actions cannot queue offline. Desktop: context header with summary/detail columns; tablet reflows to2 columns if readable; phone320px single column,44px touch targets, no page overflow. Use DESIGN tokens and reduced-motion behavior. Keyboard/readable focus,200% zoom, text equivalents to color/graphs. Expected version prevents overwriting concurrent changes. Every event/action records its domain reference and audit as scoped in ACCESS-MATRIX.
