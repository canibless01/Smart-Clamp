# 25. White Label Console
Route: `/admin/organizations/[id]` · Phase: 4 · Audience: organization admin/internal superadmin

## Reading order and content
Organization identity; approved branding; domain status; members; scoped fleet/finance.

## Buttons and interactions
Save branding; invite scoped staff; verify domain.

## Data and behavior
Organization isolation at DB and API; bounded theme colors preserving accessibility; no cross-organization exports.

## Desktop / tablet / phone
Use DESIGN.md breakpoints. Desktop: page title and context actions above main content; split summary/detail when content warrants it. Tablet: two columns collapse before labels wrap. Phone: one column in the same reading order; primary action full width; filters wrap; financial/evidence information remains accessible. Dashboard quick actions stay below the active device selector. Do not hide required fees, consent or error explanations on small screens.

## Color and motion
Navy hierarchy, white/off-white surfaces, green confirmed state, amber insight, red actionable risk, all labeled in text. Use 120–240ms shared transitions; respect reduced motion. No motion that implies live measurements or successful actions without acknowledgment.

## Required states and acceptance
Loading uses dimension-stable placeholders. Empty explains how to obtain data. Failure preserves input and offers a safe retry. Forbidden reveals no other account's details. Stale/offline labels include last observed time. Unsupported feature hides control and explains capability in context. A completed action has server-confirmed status; prevent duplicate submissions. Verify keyboard order, focus recovery, 320px/768px/1440px layouts, zoom 200%, screen-reader names, reduced-motion behavior and cross-account denial before acceptance.

## Traceability
Master sections 12–15; build guide's matching page/topic. Shared architecture/security overrides are explicit in DECISIONS.md. This is a build specification, not implemented UI.
