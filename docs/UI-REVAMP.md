# SmartClamp UI implementation

The owner approved the spacious white/forest/sage direction, self-hosted Manrope headings and DM Sans body, architectural concept photography and restrained motion. This replaces the earlier sample palette/font proposals. The implemented token source is `apps/web/app/globals.css`.

Public navigation now includes product exploration. The home page contains an original concept home visual with pause/reduced-motion support, audience tabs, meter validation and an input-driven energy calculator. It does not claim a simulated house is the visitor's actual device. The device carousel links to six separate product explanations; concept enclosures are labelled. Plans have detailed comparisons and individual pages; prices and planned capability availability are explicit.

Links in body copy are underlined. Authentication cross-links use a bordered, comfortably sized action treatment and arrow. Log-in navigation is visually distinct. Focus indicators and keyboard navigation remain required; do not rely on color alone. Cards and tables must fit 320px phones without page-wide overflow. Wide comparisons scroll within their labelled region.

Account pages use real API records or honest loading/empty/error/unavailable states. Rooms, claim codes, resident invitations, meter accounts, support messages, payments, settings, commands, history, NEPA signals and operations requests no longer depend on browser-local sample records. No timer confirms a payment, installation or physical relay result. A public account lookup does not establish live optical connectivity.

See [launch readiness](LAUNCH-READINESS.md) for exact tested scope and missing capabilities. Some pages deliberately explain unavailable integrations rather than fabricating a successful workflow. A clean interface is not a claim that every product specification is implemented.

## Verification

The frontend has responsive, keyboard, reduced-motion, lookup, role-routing, user-input calculator, product/plan and WCAG AA automated checks. An additional browser test uses actual local PostgreSQL, GoTrue and API services for landlord/room/claim/invitation/resident/quote flow. Provider HTTP fixtures exist only in tests; external merchants and physical devices require separate acceptance testing. Run commands are in the repository README.

The owner supplied Emporia, Sense and Octopus screenshots. Direct external requests, including vendr.ng, were blocked by the environment proxy; these live sites were not inspected. No copied third-party product imagery or brand assets are used.
