# End-to-end loop catalog
Normative foundation decisions; UTC on wire/storage, Africa/Lagos display and recurrence. Each event has event_id, correlation_id, actor/device, occurred_at, received_at, schema_version and source-quality. One database transaction changes state and creates the outbox. Delivery is at-least-once; business effects are exactly-once by unique event identity. The UI never treats a transport ACK as a physical actuation ACK.

## L01 Manufacture → installation → ownership
Ops creates random device ID and unique credentials; records batch/profile. Installer receives a time-limited assigned job and physically opens the provisioning window. Authenticated BLE pairs installer, writes only matching profile/calibration/topology/peer credentials, then closes provisioning. Device proves possession to backend, reports firmware/config hash and diagnostics. Backend claims ownership atomically. Only then does assigned customer see live data. Failed test stays commissioning_failed with retry/RMA; no payout. Online proof plus accepted commissioning creates one installer payable. Room transfer creates a new occupancy interval and revokes old viewer/token/session grants; it never rewrites prior bills.

## L02 Measurement → cloud → all dashboards
Sensor task samples calibrated waveforms independently of networking, computes real watts, RMS, PF, import/export counters, quality and local protection. Device appends signed record to durable journal before queueing transmission. Pole peer → assigned Pole Gateway via encrypted ESP-NOW; House Full → Building Hub by addressed RS485 polling; transformer → its configured independent uplink; IR → selected optical/radio adapter. Pole Gateway and Building Hub **do not exchange local traffic**. Each independently forwards original signed records over TLS to ingest. Backend validates identity/signature/version/sequence, commits unique inbox row + reading + processing outbox, then emits durable event ACK. Only that ACK permits source journal deletion. Lost ACK causes safe duplicate retry. Invalid payload goes to restricted quarantine; no billing.
Worker computes interval energy and scoped projections. Tenant sees own occupancy; landlord sees building aggregation; homeowner sees own pole; utility sees permitted regional aggregates; ops sees scoped fleet metrics. Every projection includes version, source, coverage and observed_at. Client subscriptions invalidate/refetch if a version gap occurs. Thus dashboard consistency comes from one event pipeline, not dashboards sending commands to one another.

## L03 Transformer loses supply
Fresh valid voltage below 50V for 3s declares supply_lost (foundation debounce); 50–179V remains brownout, not total outage. Firmware records last voltage and power-fail interrupt timestamp to bounded preallocated journal; upload during hold-up is best effort only. No battery means no promise of SMS while hardware is unpowered. If last-gasp upload is impossible, record survives and backfills after restoration; server initially shows unknown/stale rather than inventing an exact outage time.
Transformer supply_lost links to downstream topology snapshot. Worker opens one feeder outage episode; suppresses redundant downstream offline SMS while preserving device event history. Current customer dashboard: supply outage + last sync; landlord: affected rooms/building; utility: permitted affected feeder counts; ops: supply episode and gateway status. Notification to subscribed affected accounts is deduped by episode, not per reading. Planned disconnection/relay state remains distinct from supply state. No auto accusation, no charge for unmeasured intervals, no global relay command.

## L04 Supply returns
Voltage >=50V closes supply-lost indication only after 10s valid samples, but voltage protection remains until 180–250V continuously 5min. Device boots with outputs inactive, reads auxiliary relay feedback, restores journal/sequence and reports boot + outage gap. Obtain trusted time via TLS server, using NITZ only as coarse initial hint; hubs/gateways relay authenticated time to leaves. Backfill old events with original sequence and uncertain-time quality. Server closes outage with confidence bounds, updates supply projections, sends one restored notice, then reevaluates present control intent. It never executes queued expired ON/OFF requests. Auto-restore only if user enabled it and no other OFF reason remains. A latching relay may retain ON across outage; do not claim physical opening on restoration unless feedback proves it.

## L05 Communications fail, supply remains
Three missed 60s heartbeats marks stale at 180s; >=24h triggers source-specified offline notification. Parent gateway offline propagates dependent connectivity_unknown, not assumed sensor failure or utility outage. Local sensing/protection continue. Bounded journal retains records; overflow raises data_loss and preserves explicit lost sequence ranges. Neither zero wallet nor unchanged server balance can be assumed during disconnected consumption. Revision2 defaults: no speculative offline wallet debt cutoff; display delayed-accounting exposure, preserve local protection and preauthorized schedules. Offline prepaid enforcement requires a separately signed allowance design and qualification before launch. Alerts require reachable route; GSM SMS fallback cannot work if cellular service/power is absent. Monthly authenticated handheld collection is a secondary path using original signatures/ACKs.

## L06 Correlation and tamper
Align cumulative energy deltas over identical 5min UTC windows; require >=95% source coverage, valid calibration, correct parent topology and interval clock confidence. Transformer compares SUM of all assigned downstream poles, pole compares complete downstream rooms + explicitly metered common loads, clamp compares matched meter. Legitimate transformer loss/common loads are configured, not charged to arbitrary rooms. Three consecutive eligible windows above thresholds (10%,8%,5% respectively) opens one suspected_mismatch episode. Missing children produce insufficient_coverage; cannot produce verified. No-load/zero current alone is never theft. Relay OFF + significant current plus valid voltage/feedback generates suspect bypass. Hall and cell-tower changes are evidence signals. Ops reviews, can dispatch/recalibrate and mark false positive. Only reviewed privacy-safe notices reach community; never automatic public naming or supply cutoff.

## L07 Recharge → physical meter → room credit
Backend issues expiring quote with utility, destination, rate/version, fees/markup separately, amount in kobo, units and rounding. Idempotency-Key binds payer+request hash for 24h. Paystack checkout redirect indicates pending only. Webhook signature verified on raw bytes; event reference/provider unique. Backend verifies expected account/currency/amount/status with provider, atomically posts money ledger and fulfillment outbox once. Shared-meter model has two distinct obligations: room allocation and central-meter vending. Revision2 reserves purchased units until vendor confirms vending/top-up; no representation of usable physical supply before confirmation. Publish paid_pending_vend; retry provider fulfillment with same reference; timeout escalates reconciliation/refund, never double-vend. Confirmed vend releases room credit exactly once; notify payer. Any return-to-ON intent clears only zero_balance reason, not protection/manual/budget/schedule/consent reasons. Physical ON is shown only after feedback ACK. Meter requiring manually entered STS token shows token_pending_entry and human confirmation/verified meter read; wallet bookkeeping is not proof of physical top-up.

## L08 Debit, low balance and debt
Only validated monotonic measured delta decrements units once. Counter rollover/reset/replacement produces reconciliation hold until correct epoch established. Lock wallet ledger row per posting. Low balance = below 10% of most recent confirmed recharge allocation, once per crossing; absolute notification threshold also configurable. Credit crossing zero emits zero_balance event, authenticated OFF intent for eligible room (prepaid agreement), and notice after physical ACK. Source's simplified 'cut at zero' is constrained by payment reconciliation and hardware ability. No relay → alert only. Subscription failure, rent dispute or data gap never creates power cutoff. Delayed readings post historical usage with clear adjustments; no stale command replay.

## L09 Manual, automated and protective control
Authorized user submits intent; backend checks device relay, role, relationship, consent if utility, current flags and fresh step-up. Return 202 pending, allocate monotonically increasing sequence and immutable signed command, queue by destination. Gateway forwards original bytes. Device validates TLS/origin HMAC, target/config epoch, expiry, payload binding, durable replay counter and local safety gates before a bounded coil pulse. Read feedback and return applied/rejected/feedback_unknown. Persist receipt; worker updates state and audit; UI changes confirmed state only after ACK. Lost ACK queries status by command_id; never blind repeats a pulse. Local unsafe voltage opens where commissioned even when server is absent. No uncommissioned default pin actuation.

## L10 Automation and intent conflicts
OFF reasons form a set: protection, wallet_zero, budget, schedule, user_manual, maintenance, utility. ON occurs only when all relevant reasons clear and fresh voltage/feedback/commissioning allow it. Most restrictive current valid OFF wins. A recharge clears only wallet_zero; user restore clears protection only after stable gate; revoke utility cancels pending utility commands and removes that policy only subject to other reasons. Schedule edit/creation uses step-up once to create bounded delegated automation, not SMS at each run. Recurrences use IANA Africa/Lagos, unique(schedule_id, occurrence_utc), max lateness 60s; miss while offline means skip and record, not replay. Budget counts consumption valuation in its configured period, not amount of top-ups; a change recalculates present reason. Maintenance has reason, scope and expiry (default 30min); no punitive individual debt controls.

## L11 Subscription, downgrade and capability
Free validation is anonymous. Basic monitors, Basic Pro analytics, Pro permits eligible user control. House Full prepaid/safety logic derives from installed room service capability, not purchase of a separate homeowner Pro plan. Safety is never subscription-gated. Lapsed subscription shows grace/read-only policy, never creates an OFF reason. Before removing a paid automation entitlement, cancel future delegated executions and explicitly notify user; do not force relay state. Hardware relay upgrade requires commissioned installation; upgrading plan alone cannot enable pins.

## L12 Dispute and evidence
Bill dispute freezes evidence snapshot, not household power. Attach immutable period readings, coverage, tariff and ledger versions. Respondent can explain/propose adjustment/escalate. Accepted adjustment posts reversing ledger entries, never edits raw events. Meeting Mode reads the same scoped snapshot, excludes unrelated personal data. Report canonical bytes are signed with rotated server signing key, stored immutable with SHA256 and issue metadata; public token is random, scoped, revocable. Verify historical stored bytes, never recompute from mutable live rows and call that proof. Audit every export; expiry/revocation is explicit.

## L13 Utility/NEPA
Admin creates region-scoped account; no self-serve utility role. Aggregates available only for contracted regions; individual drilldown requires authorized purpose/scope and is logged. Bills and broadcasts are previewed; immutable bill period/tariff snapshot; human utility payment confirmation remains separate from generation. Disconnection list is a report, never actuator input. Remote control requires current explicit device-owner consent to named utility/capability, staff authority and command step-up; recheck at outbox dispatch; revocation invalidates queued utility commands by policy epoch. A broadcast never silently becomes consent. Source outages visible in utility dashboard are telemetry facts, not evidence the utility has billing partnership everywhere.

## L14 No-meter and generator allocation
No-meter rollout disabled until bill upload/proof and unanimous building enrollment. Foundation default for build: per-bill final reconciliation, provisional balances as estimate; operator activation still requires approved rates/margin. Bill-share = measured room delta / measured building delta × actual bill. Unallocated common-load/loss remainder is visible; do not silently distribute it without disclosed agreement. Generator accounting uses separate source circuit/meter/period, approved fuel/operating invoice and measured generator kWh share; never double-count grid usage. Missing source attribution disables automatic generator allocation. Landlord contribution pool is custodial pass-through; paid status needs payment evidence, not arbitrary UI toggling.

## L15 Ops, RMA, OTA and reconciliation
Failed gateway, disputed payments, undelivered commands/notifications and queue overflow create tickets with owner/SLA. Device replacement closes old installation epoch, preserves balance/history, provisions new keys and calibration, requires physical test. OTA manifest binds profile, board, version, hash, signed image and minimum secure version. Resume local chunks but verify full signature/hash before boot partition switch; watchdog rollback if health fails. Cohort rollout 1 device → 5% → 25% → rest with manual stop; never update all gateways in one feeder simultaneously. Unsupported board/profile rejects manifest. Factory reset wipes credentials only through authorized decommission/re-enrollment; never reuses old monotonic command counter under same key epoch.
