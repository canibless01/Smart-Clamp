# Signed room credit policy

Implemented software: qualified House Full poll → signed request-bound allowance → immutable device receipt → device-detail status, plus a durable native policy controller. **Physical cutoff/restore is not integrated or qualified.** The commissioning image explicitly rejects installation with `hardware_unqualified`; no acceptance receipt is treated as relay feedback.

The volume ceiling is the qualified installation's original cumulative-counter baseline plus the sum of actual, accepted, confirmed purchased-unit funding lots. It is not current cloud balance plus the latest reading. Delayed usage jobs, missing intervals or a stale balance therefore cannot manufacture more allowance. Standalone meter-purchase totals never become a room policy.

Migration 023 defaults qualification off. An installed service needs `prepaid_enforced`, `persistent_counter_qualified`, `prepaid_policy_qualified`, a commissioned/qualified House Full relay and an actual `prepaid_anchor_mwh` captured **at the start of its wallet service**, with `meter_counter_epoch`. Never fill the anchor with the latest counter to bypass existing consumption; old wallet/installation history requires reconciliation. Once policies exist, changing the baseline/counter epoch is blocked pending a reviewed decommission/replacement process. Flags record physical qualification; they cannot create it.

Poll includes `prepaid_policy` only for eligible installations. The SC1 command-direction signature binds device/key/config/counter/policy epochs, monotonic policy sequence, baseline, funding total, absolute ceiling, body hash and requesting boot/sequence. A short-lived offer cannot be replayed onto another poll. Repeated polls without funding/configuration changes retain the same policy sequence. Device receipts require the issued policy hash; accepted receipts need a qualified counter/epoch and trusted observation time. Receipts are immutable events, deduplicated by original inbox identity. The latest issued policy and acknowledgement are visible at device detail.

`firmware/include/prepaid_policy.hpp` tests durable policy/counter persistence before authorization, exact allowance exhaustion, recharge clearing only the wallet restriction, counter rollback/epoch rejection and storage failure. Each boot requires a fresh qualified counter observation before authorization; a recovered record alone cannot enable ON. Unavailable counter/storage integrity blocks authorization and must use its separate sensing/storage safety gate; it is not labelled measured zero consumption. Other voltage/manual/maintenance restrictions remain untouched. Volume already granted can be spent offline with a qualified persistent counter; it does not depend on an untrusted wall clock. A later cloud revocation cannot be promised to reach an offline device immediately.

Required remaining integration: calibrated acquisition and persistent energy counter/journal, power-fail atomicity, the qualified relay/feedback/watchdog HAL, clock/config commissioning and actual cutoff/recharge/reboot/offline bench tests. The existing accounting watermark remains conservative about unknown intervals; this allowance design does not turn missing measured usage into a billed interval. Refunds/adjustments require the separate reviewed financial/device reconciliation workflow; no instant offline clawback is claimed.
